# Whose Facts Win? LLM Source Preferences under Knowledge Conflicts

Code for the paper:

> **Whose Facts Win? LLM Source Preferences under Knowledge Conflicts**
> Jakob Schuster, Vagrant Gautam, Katja Markert
> [https://arxiv.org/abs/2601.03746](https://arxiv.org/abs/2601.03746)

This repository contains the evaluation framework and finetuning pipeline used
to study how LLMs resolve inter-context knowledge conflicts depending on the
source of the retrieved information.

## Setup

### 1. Install dependencies

```bash
pip install -r requirements.txt
```

### 2. Download the dataset

The dataset is hosted on HuggingFace:
**[https://huggingface.co/datasets/JaSchuste/llm-source-preference](https://huggingface.co/datasets/JaSchuste/llm-source-preference)**

Files are Fernet-encrypted. Export the decryption key "kiki-bouba" as an environment variable before downloading:

```bash
export LLM_SP_KEY=''
```

Then download via:

```python
from helpers.data_loader import download_dataset
download_dataset()
```

Alternatively, place the data files manually in the `data/` directory
(see `helpers/config.py` → `DATA_FILES` for the required filenames).

## Generating Entity Field Alternatives

The dataset (`neoqa_entities_with_alternatives.jsonl`) was produced by
`generate_entity_field_alternatives.py`, which adds four alternative values for
every non-excluded field of each entity.

- **Categorical fields** (e.g. `marital_status`, `hair_color`): sampled from a
  fixed vocabulary.
- **Numeric fields** (`counts`, `years`, `dates`, `monetary values`, `measurements`):
  generated by up- down-scaling in a fixed relative or absolute range, with similar precision.
- **All other fields**: a Qwen2-72B-Instruct LLM is prompted to produce
  plausible fictional alternatives.

```bash
python data_creation/generate_entity_field_alternatives.py \
    --input  neoqa_entities.jsonl \
    --output neoqa_entities_with_alternatives.jsonl \
    --model  Qwen/Qwen2-72B-Instruct
```

| Flag | Default | Description |
|------|---------|-------------|
| `--input` | `neoqa_entities.jsonl` | Input entity file |
| `--output` | `neoqa_entities_with_alternatives.jsonl` | Output file |
| `--model` | `Qwen/Qwen2-72B-Instruct` | HuggingFace model for non-numeric fields |
| `--log-file` | `entity_generation.log` | Log output path |

## Running Experiments

Each experiment is a standalone script in `experiments/`.  All scripts share
the same CLI arguments (see `helpers/runner.py`).

### Common Arguments

| Flag | Default | Description |
|------|---------|-------------|
| `--model` | `google/gemma-3-4b-it` | HuggingFace model name or local path |
| `--data-dir` | `data` | Directory with data files |
| `--results-dir` | `results` | Output directory for results |
| `--seed` | `42` | Random seed |
| `--neutral` | off | Add "Can't be answered" option |
| `--altinst` | off | Alternative instruction phrasing |
| `--snm` | off | Source-not-mentioned mode |
| `--alttok` | off | Use (1)/(2) instead of (A)/(B) |
| `--source-aware-prompt` | off | Source-credibility-aware instruction |
| `--repetition-aware-prompt` | off | Instructs model to ignore simple repetition |
| `--finetuned` | off | Model has been finetuned (adds suffix) |

### Example

```bash
# Baseline: no source vs no source (required for SP computation)
python experiments/control.py --model google/gemma-3-4b-it

# Government source vs social media user
python experiments/government_vs_social_media.py --model google/gemma-3-4b-it

# High vs low newspaper circulation
python experiments/high_low_circulation_newspaper.py --model google/gemma-3-4b-it

# With alternative instruction
python experiments/newspaper_vs_social_media.py --model google/gemma-3-4b-it --altinst
```

Raw results are only written to disk for the `control` experiment (needed as
the baseline for SP computation).  All other experiments evaluate in memory and
write only aggregated results to
`results/agg/<experiment_type>/neoqa_<model_name>.json`.
The **Source Preference (SP)** metric reports the mean difference in the
model's preference probability relative to the control condition, expressed as
a percentage.

### Multi-seed pipeline for Fine-tuning based Repetition Bias Mitigation

```bash
python finetuning/run_multi_seed.py \
    --model-name google/gemma-3-4b-it \
    --output-dir multi_seed_runs \
    --data-dir data
```

This runs 7 seeds sequentially: generate data → train → merge adapter.

### Individual steps

```bash
# 1. Generate training data (seed-specific entity selection)
python finetuning/generate_training_data.py \
    --data-dir data --output-dir finetuning_data --seed 42

# 2. Train
python finetuning/train.py \
    --train-data finetuning_data/train.jsonl \
    --val-data finetuning_data/val.jsonl \
    --output-dir finetuned_model

# 3. Merge LoRA adapter
python finetuning/merge_adapter.py \
    --adapter-path finetuned_model/best_model \
    --output-path finetuned_model/merged

# 4. Evaluate the finetuned model
python experiments/government_vs_social_media.py \
    --model finetuned_model/merged --finetuned
```
